# Anti-Slop UI Rules

DesignDock should avoid the visual tells that make generated UI feel generic, ungrounded, or hard to implement.

## Avoid

- Generic purple/blue gradients by default.
- Random glow effects.
- Gradient text by default.
- Glassmorphism by default.
- Overuse of cards.
- Cards inside cards.
- Identical three-card feature grids everywhere.
- Hero metric/stat blocks as a default hero pattern.
- Tiny uppercase eyebrow labels above every section.
- Section numbers like 01 / 02 / 03 unless the content is a real sequence.
- Repeated split image/text zigzag sections.
- Centered heroes as the default for every landing page.
- Fake dashboards made from random rectangles.
- Fake testimonials unless the user asks for placeholders.
- Fake customer logos unless clearly marked as placeholders.
- Low-contrast muted text.
- Gray text on colored or tinted backgrounds.
- Pure black and pure white as default surfaces.
- Over-rounded cards and containers.
- Big soft shadow plus border on every card.
- Inconsistent radius, spacing, shadows, and accents.
- Desktop-only layouts.
- Hero content that overflows the first viewport.
- CTA buttons with wrapped labels.
- Duplicate CTAs with the same intent.
- Placeholder-as-label in forms.
- Missing loading, empty, and error states for product UI.

## Prefer

- Use restrained color systems.
- Pick a color strategy before choosing colors: restrained, committed accent, full palette, or drenched.
- Use one accent consistently.
- Vary section layout families.
- Use cards only when they communicate grouping or hierarchy.
- Use real structure, whitespace, dividers, contrast, and typography.
- Keep hero copy short and specific.
- Use mobile collapse rules explicitly.
- Use design systems as constraints, not labels.
- Make every section justify its place.

## Register Guidance

Brand pages can carry stronger visual identity, but every effect still needs a reason. Product pages should make repeated work easier: clear state, dense but readable information, restrained accents, and predictable controls.
